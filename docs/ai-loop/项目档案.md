# 项目档案

AI Loop 的「项目档案服务」设计说明。对应实施方案 6.1、6.2 节和阶段 4。
本文件覆盖 4A（独立模块）的全部约定；4B 接入内核时按「与内核的接入点」一节做。

## 项目是什么

**项目 = 一组规则 + 一个工作目录 + 一份档案。** 跟 Agent 工具里的「项目」一个意思。

在 `rules.json` 里登记：

```jsonc
{
  "projects": {
    "ai-loop": {
      "name": "AI Loop",              // 显示名
      "cwd": "~/mini-hub/ai-loop",    // 项目工作目录，接单电脑解释
      "archive": "archive/ai-loop"    // 可选：档案地址，默认 <数据目录>/archive/<项目编号>
    }
  },
  "rules": [
    { "name": "巡检", "project": "ai-loop", "when": { "cron": "*/30 * * * *" }, "to": "claude", "cwd": "~/mini-hub/ai-loop", "prompt": "…" }
  ]
}
```

- 一个项目可以有多条规则；没写 `project` 的规则按原样运行，不要求读写档案。
- 项目编号的写法跟来源、Agent 编号一样：小写字母、数字和 `-` 开头小写字母。
- `project` 必须是已登记的项目编号；写错名字校验直接拒收，旧规则继续跑。

## 档案目录结构

正本在中枢那台电脑：`<数据目录>/archive/<项目编号>/`（`AGENT_AUTOLOOP_HOME` 下的 `archive/`），**每个项目一个 Git 仓库**。

```text
archive/ai-loop/            ← Git 仓库根（含 .git）
├── 档案.json              ← 元数据：{ project, version, head, updatedAt }，每次写回更新
├── 说明书.md              ← 目标、规则、权限、环境约定；建档时写入，平时不动
├── 状态.md                ← 当前状态摘要、关键决策标题；写回可整篇替换
├── 日志.md                ← 只追加的执行记录
├── 决定.md                ← 已拍板的决定，只追加
└── 检查点/                ← 阶段性快照，普通目录，各轮可往里放文件
```

`档案.json` 是副本自描述的凭据：从桶里拉下来的目录不看 `.git` 也能知道这是哪个项目、当前第几版、对应哪个提交。

## 版本号

- 单调递增整数，**版本 = 写回次数**。建档提交（写入模板）是版本 0，不算写回。
- 每次写回产生一个 Git 提交，打标签 `v<N>`；`档案.json` 里同时记下提交号和写回时刻。
- 按版本读用 `git show v<N>:<文件>`，所以副本带着 `.git` 就有全部历史。

## 读取

- 派单时单子里只放三样：**档案地址、版本号、一段短摘要**（当前状态开头 + 最近几条决定标题，约几百字，不放全文）。
- 接单程序按「项目 + 版本号」缓存：版本没变用缓存，变了才重新拉。缓存是 4B 的事；4A 提供 `readArchive`（当前版）和 `readArchiveAt`（指定版）两个能力。
- **中枢不在时**：设备用只读密钥把桶里 `archive/<项目编号>/` 的副本拉到本地目录，照常读当前文件和任何历史版本（`.git` 一起下来了）；结果先存本地，中枢恢复后补交。

## 写回

走回执新增的 `archive` 段（4B 实现），跟回执同时生效：

```jsonc
{ "archive": { "base": 3, "log": ["…", "…"], "status": "新摘要整篇", "decisions": ["定了某事"] } }
```

- `base` 必填，是这一轮**读到的版本号**。缺 `base` 或它不是数字，整段拒收——没读没写回。
- `log` 数组，每条一行追加进 `日志.md`，写回时补上日期前缀。
- `decisions` 数组，每条追加进 `决定.md`。
- `status` 整篇替换 `状态.md`。

### 版本校验与合并

| `base` 与当前版本 | 结果 |
| --- | --- |
| 相等 | 全部生效，版本 +1 |
| 落后 | `log`、`decisions` 追加总能合并；`status` 不覆盖——记下「状态冲突」，结果里写明，由调用方发卡片转本人确认；有可合并内容时仍提交新版本，没有则不提交、整体算被拦 |
| 超前 | 不可能的状态，报错 |
| 档案不存在且 base=0 | 自动建档（版本 0）再写回，得版本 1 |
| 档案不存在且 base>0 | 报错：没读过档案不可能有这个 base |

状态冲突时的补救：本人（或它授意的 Agent）按当前版本重交一次写回，即 base 写成现在的版本号，新摘要覆盖上去。这是「发卡片问本人」之后的确认路径，不需要额外的强制写入选项。

## 「没读没写回不算完成」

带 `project` 的规则，`done` 回执必须带 `archive` 段：

- 缺 `archive` 段：中枢把这一轮标记为未完成并提醒（卡片），业务结果照收——拦的是「算完成」，不是拦回执本身。
- 有 `archive` 段但 `base` 缺失、不是数字、或写回被版本校验拦下：同样标未完成并说明。
- `nothing` / `failed` / `cancelled` 结局不强制带 `archive` 段：没事可做、没跑成、被停的轮次没有可写回的进展是合理的，但带了一样按上面的规则校验合并。

判定在中枢（4B），档案模块只保证硬约束：没有 `base` 的写回永不生效。

## 同步到私密桶

- 桶：`grok-bot-files`（Cloudflare R2，S3 兼容）；前缀 `archive/<项目编号>/`。
- **推**：同步程序（独立进程，中枢内核不往外连）在每次写回后把整个项目目录含 `.git` 推上去；按内容的 MD5 对比只传变化的，远端多出来的对象删掉，保持镜像一致。
- **拉**（只读）：设备把前缀下所有对象拉到本地目录（含 `.git`），多余本地文件清掉。拉下来的目录就是一份完整档案，`readArchive` / `readArchiveAt` 直接用。
- 签名自己用 `node:crypto` 实现（AWS SigV4，service `s3`），路径式地址 `<endpoint>/<bucket>/<key>`。
- 凭据只从环境变量读，不进仓库、文档、日志：

  | 变量 | 用途 | 默认 |
  | --- | --- | --- |
  | `ARCHIVE_S3_ENDPOINT` | S3 兼容接口地址（R2 是 `https://<账号>.r2.cloudflarestorage.com`） | 必填 |
  | `ARCHIVE_S3_REGION` | 签名区域 | `auto` |
  | `ARCHIVE_S3_BUCKET` | 桶名 | `grok-bot-files` |
  | `ARCHIVE_S3_ACCESS_KEY_ID` / `ARCHIVE_S3_SECRET_ACCESS_KEY` | 凭据 | 必填 |

  Mini 上放读写凭据（secrets.env，权限 600）；其他设备只读凭据，仅 `archive/` 前缀。

## 与内核的接入点（留给 4B）

4A 只把能力备齐，下面几处是 4B 要动的：

1. **派单**：`Job` 增加 `archive?: { project, address, version, summary }`；`claimNext` 组 Job 时若 `rule.project` 已登记，读档案填上（没建档时版本 0、摘要为空）。
2. **回执**：`Result` 增加可选 `archive` 段；`applyReceipt` 里项目规则的 `done` 缺段标未完成，写回冲突（`conflicts` 非空）发卡片转本人。
3. **接单程序**：按「项目 + 版本号」缓存档案目录；Job 带新版本时拉取/刷新，写进资料文件；中枢不可达时按上面「读私密桶副本」走。
4. **同步触发**：写回成功后（host 层收到 `finish` 应答且含 archive 写回）触发一次 `pushArchive`；另有定时兜底同步。
5. **`agent-autoloop status`**：项目栏列出各项目档案版本，可选。

## 4A 交付的模块

```text
archive/
├── git.ts      ← 系统 git 的薄封装：init、add、commit、tag、show、rev-parse
├── store.ts    ← 档案库：建档、读取、按版本读、带 base 写回与合并、短摘要
├── s3.ts       ← S3 兼容客户端：SigV4 签名（node:crypto）、put/get/delete/list
├── sync.ts     ← 推送（镜像到桶）与只读拉取（桶到目录）
└── cli.ts      ← agent-autoloop archive 子命令的实现
```

只用 Node 自带模块；Git 操作调用系统 `git` 命令，仓库初始化用固定的机器人署名，不改用户的 Git 配置。
