# 用量统计设计说明

对应实施方案的计量（metering）阶段。本文是这一阶段的设计正本；与上游文档冲突处以 `docs/protocol.md` 现有行为为准。

## 1. 要解决的问题

`/v1/state` 的 `spending` 只数中台派出去的轮次（回执 `usage`）。每台设备上还有大量中台看不见的消耗：手动跑的 Agent 会话、走本地网关的流量。中台要成为全设备的用量统计中心：每天每周总消耗、按天按设备按 Agent 按模型的 input/output/cache_read/cache_write，跨设备对比。

隐私原则沿用参考采集器：只传 token 数字与名字，永不传正文。协议和内核只用通用词（device、agent、model、source），不出现具体产品名。

## 2. 数据流

```
设备上的计数文件 ──读增量→ worker/meter.ts ──聚合成天→ POST /v1/usage ──全量覆盖→ usage/quotas 投影表
                                                                              ↓
回执 runs.usage ───────────────────────────────────── 读时并入（source="runs"）→ GET /v1/usage、/v1/state.usage、CLI
```

- `worker/meter.ts`：三类采集源（`config.worker.meter.sources` 配置）——`gateway`（逐请求 jsonl，按字节偏移增量读，半行等下次）、`sessions`（会话 jsonl 目录，按文件+偏移增量；两种用量行：消息自带 usage、累计计数取增量）、`quota`（额度文件变化时整读，支持快照与历史两种形状）。每 15 秒扫一遍，有变化最多每分钟上报一次；`worker/metering.json` 存偏移、已报分区与已启动会话。
- 去重：worker 启动的会话记进 `sessions[use]`，会话文件名与网关日志里的 `session`/`native_session` 命中即跳过——这部分用量已由回执计入 `runs`。
- 幂等：上报按「设备+天」全量覆盖。重发同一天分区是重写不是累加；漏掉的日期下一次全量修正；没提到的日期不动。额度快照同理会整体替换。内核只记事实，投影表 `usage`（device|date|agent|model|source）与 `quotas`（device|provider|account|window）随日志重建。
- 读侧 `usageOf`：metered 行 + 完成轮次的 `usage`（记到该 Agent 所属 worker 名下，`source="runs"`）。口径统一为「input 含缓存」：metered 行显示 `input+cache_read+cache_write`；runs 行回执的 `input` 本就含缓存，`cached` 单列缓存读部分。

## 3. 端点与命令

- `POST /v1/usage`（worker 密钥）：`{days?: [{date, rows:[{agent,model,source,input,output,cache_read,cache_write,runs}]}], quotas?: [{provider,account,plan?,window,used_pct,resets_at,at?}]}`；上限 62 天 × 200 行 + 100 额度行。
- `GET /v1/usage?days=N&device=…`（owner 密钥，N≤93）：`{now,timezone,since,until,days,devices,total,rows,quotas}`。
- `/v1/state` 顶层加 `usage`（today/week 各设备分列 + quotas）；`spending` 口径不变。
- `agent-autoloop usage [--days N] [--device 名字] [--json]`。

## 4. 本期不做

- 不做自动改派：`quotas` 只采集展示，给后续 `model_holds`/改派备数据。
- 不做实时流：采集随轮询顺带 + 每分钟兜底，分钟级延迟可接受。
